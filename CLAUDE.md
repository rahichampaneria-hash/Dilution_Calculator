# Dilution Toolkit — CLAUDE.md

A static, zero-build lab-tools website for a molecular biology lab. Plain HTML/CSS/vanilla JS only — no frameworks, no build step, no backend. Deploys as-is (drag the whole folder) to Netlify/Vercel/GitHub Pages. The one runtime dependency in the whole site is SheetJS, loaded from a CDN (`<script>` tag, `defer`) by `msd-plate.html` and `plate-map.html`, purely to parse .xlsx/.xls uploads client-side; it degrades gracefully to "use CSV instead" if the CDN is unreachable, and no other page references it.

## Files

- `index.html` — home page (nav + hero-less tool grid + feature badges)
- `dilution.html` — Simple Dilution (C1V1=C2V2) + Serial Dilution Series (constant or variable per-step factors)
- `stock-solution.html` — Secondary Stock Solution Planner (2-stage dilution when a direct dilution would need sub-pipettable volumes)
- `plate-map.html` — two tools on one page (top-level tabs, same pattern as `dilution.html`'s Simple/Serial): **Dilution Series** (serial dilution series laid out across a plate, plain bordered wells with concentration printed as text, click-to-mark blank/control) and **Condition List** (import a condition/treatment list from an uploaded CSV/Excel — sheet picker + column-letter mapping, since real lab spreadsheets don't arrive in a fixed shape — and lay it onto wells sequentially). Both share freeform per-well/row/column labels.
- `msd-plate.html` — MSD (Meso Scale Discovery) Plate Planner (standard curve + uploaded sample CSV/Excel laid out on a 96-well plate, MSD lab conventions, freeform per-well/row/column labels). Sample upload has a simple default path (first sheet, fixed SampleName/Concentration/Unit columns) plus an "Advanced: pick sheet & columns" panel for a sample sheet that doesn't match that shape.
- `shared.css` — the entire design system (light + dark tokens, every component class)
- `shared.js` — the entire calculation engine + DOM-adjacent utilities, loaded by every page

No other files matter functionally. `.claude/launch.json` configures a local static server (`python3 -m http.server`) for the `run`/preview tooling — see Testing below.

## Architecture (apply this pattern to any new page)

**Every page follows the same skeleton**, copy-pasted intentionally (no templating since there's no build step):
1. Inline `<head>` script reading `localStorage.getItem('dilutionToolkit.theme')` and setting `data-theme` on `<html>` before paint (avoids flash of wrong theme). Identical on every page.
2. `<header class="navbar">` — identical nav on every page except which link has `aria-current="page"`. **When adding a page, add its nav link to ALL existing pages, not just the new one.**
3. `<div class="wrap">` → `.page-header` (h1 + tagline) → the tool's own content → `.history-panel` (identical markup everywhere) → `.page-footer` (identical line).
4. `<script src="shared.js">` then an inline per-page script with, in order: `showError`/`hideError`/`flashButton`/`renderHistory()` helpers (copy-pasted verbatim, not shared — this is intentional), a `buildXParams()` function mirroring form state (used for both share links and history), a Calculate/Generate handler (empty-field check → `try`/`catch` around a pure `shared.js` function → write DOM → `pushHistory()` → `renderHistory()`), a Reset handler, Export-CSV/Copy-link handlers, a share-link-loader IIFE that reproduces a calculation from `?query=params` on load, and finally always `initTheme(); renderHistory();` as the last two lines.

**`shared.js` is split into two labeled sections:**
- `CALCULATION ENGINE` (top) — pure functions, **zero DOM access**, testable in isolation. This is where all math lives: unit conversion (`MOLAR_FACTORS`/`MASS_FACTORS`/`VOLUME_FACTORS`, `concentrationFamily`, `convertConcentration`, `convertConcentrationFlexible` for MW-bridged cross-family conversion, `chooseConcentrationUnit`, `convertVolume`, `chooseVolumeUnit`, `formatNumber`), and the per-tool calculators (`simpleDilution`, `serialDilution`, `serialDilutionVariable`, `secondaryStockDilution`, `buildConcentrationChartSVG`, `generatePlateMap`, `generateMsdPlate`, `parseMsdSampleCsv`/`parseMsdSampleRows`), plus plate-label helpers (`encodeLabelOverrides`/`decodeLabelOverrides` for row/column headers, `encodeWellNotes`/`decodeWellNotes` for freeform per-well notes) and the spreadsheet-import layer (`spreadsheetColumnToIndex`/`indexToSpreadsheetColumn`, `splitCsvText`/`readRowsFromCsvText`, `mapRowsToConditions`, `mapRowsToSamples`, `layoutConditionList` — see "Spreadsheet import" convention below). **New tools should add pure functions here, not inline math in the page script.**
- `UTILITIES (DOM-adjacent)` (bottom) — `downloadCSV`, `buildShareURL`/`parseShareParams`, `copyToClipboard`, history (`pushHistory`/`getHistory`/`clearHistory`, localStorage key `dilutionToolkit.history.v1`, capped at 10), theme (`applyTheme`/`initTheme`/`toggleTheme`, localStorage key `dilutionToolkit.theme`), file/workbook reading (`readFileAsText`, `readFileAsArrayBuffer`, `isExcelFile`, `readWorkbookFromFile`, `readRowsFromWorkbookSheet` — genuinely shared across `msd-plate.html` and `plate-map.html`, unlike the intentionally-duplicated helpers below).

**Design tokens** (`shared.css` `:root` + `:root[data-theme="dark"]`): `--blue-900/700/600/100`, `--teal-500/600`, `--ink`, `--muted`, `--border`, `--bg`, `--card`, `--error-*`, `--ok-*`, `--warn-*`. Reuse existing component classes (`.tabs`/`.mode-tabs`, `.field-row`, `button.primary/.secondary/.btn-icon`, `.error-box/.warn-box/.result-box`, `.plate-scroll/.plate-grid/.well/.well-note/.plate-label-input`, `.checkbox-field`, `.type-legend`) before inventing new ones.

## Conventions worth knowing before changing anything

- **Concentration units**: nM, µM, mM, M (molar family) and ng/mL, µg/mL, mg/mL, pg/mL (mass family). Molar↔mass conversion requires a molecular weight (`convertConcentrationFlexible`) — never silently guessed.
- **`serialDilution`'s step numbering ≠ `generatePlateMap`'s**. `serialDilution` never includes the undiluted stock as a row. `generatePlateMap`/`generateMsdPlate` deliberately DO include the undiluted top concentration as point 1 (a plate well has to start somewhere). This is intentional and documented inline — don't "fix" one to match the other.
- **MSD standard curve concentrations stay in ONE FIXED UNIT** across all points (matching MSD's own kit-insert tables) — `chooseConcentrationUnit` (which auto-rescales per value) is deliberately NOT used there.
- **Validation philosophy**: every calculator throws a friendly `Error` rather than silently truncating/clamping/overwriting. There's history here — an early bug had the serial-dilution "steps" field use `parseInt` (silently truncating "2.5" to 2) instead of `parseFloat` (which correctly fails the integer check and throws). Any new numeric field should default to `parseFloat` + an explicit `Number.isInteger` check if it needs to be a whole number, not `parseInt`.
- **Overlap/collision checks matter**: `generateMsdPlate` validates the standard-column block and sample-column region don't overlap before placing anything.
- **Plate wells carry no fill colour, on purpose.** A concentration-gradient tint (plate-map) and categorical type tints (msd-plate) were both tried and removed — at real-world text density a colour fill reads as a hard-to-see solid block, not a subtle cue. Wells are told apart by border style (`.state-empty` dashed, `.is-blank` diagonal hatch) and their own text content only. Don't reintroduce a `background-color`/`opacity` fill on `.well` without discussing it first.
- **Row/column headers and per-well notes are separate sparse stores**, both page-local (not persisted globally): `rowLabels`/`colLabels` (array, index = row/col number, `''` = default A-H/1-12) and `wellNotes`/`msdWellNotes` (object, key = well ID like `"B3"`). Each has its own `encode*`/`decode*` pair in `shared.js` and its own share-link param (`rlbl`/`clbl`/`notes`) and CSV export column — keep these three independent when extending either plate page, don't conflate a row/column label with a well note.
- **SheetJS clips to a sheet's *used range* by default — `readRowsFromWorkbookSheet` deliberately overrides this to anchor at A1.** A real spreadsheet very often doesn't start its table in column A / row 1 (this was caught testing against a real 15-sheet lab master file whose "Plate layout" sheet starts at B3) — left alone, `sheet_to_json`'s output index 0 silently becomes whatever the sheet's first *used* column/row is, which would make every column letter a user reads off their own spreadsheet wrong by however many columns/rows the data is offset. Don't call `XLSX.utils.sheet_to_json` directly elsewhere without the same `range: {s:{r:0,c:0}, e:decoded.e}` override, or column-letter mapping (see below) silently breaks again.
- **Spreadsheet import (`mapRowsToConditions`/`mapRowsToSamples`) always asks the user for an explicit column-letter mapping and a "skip first N rows" count — never auto-detects either.** This is deliberate: a real lab master sheet mixes multiple tables, stray label rows, and notes columns in ways a header-sniffing heuristic will misfire on sooner or later. `skipRows` is a *count*, not a boolean — a real sheet can have more than one junk row between the header and the real data (e.g. summary/control rows with a name but no value), which is exactly why it isn't just a "has a header row" checkbox.

## Testing

Use the Browser pane's `preview_start` with the `static-site` launch config (already in `.claude/launch.json`) — a local Python static server. **Never test via `file://`** — `localStorage` and `navigator.clipboard.writeText` behave unreliably there; several real-looking "bugs" during development turned out to be this.

**Known local-dev gotcha**: the browser aggressively HTTP-caches `shared.js`/`shared.css`/the HTML pages by exact URL. After editing any file, a plain reload can silently serve the stale cached version (this produced multiple false "regressions" during development). Force a real refresh with:
```js
Promise.all(['shared.js','shared.css'].map(f => fetch(f, {cache:'reload'}))).then(() => location.reload());
```
run via the JS console/tool, before re-testing — not just a normal navigate/reload.

**Real lab data the user shares to test a feature against (spreadsheets, sample sheets, etc.) is confidential and must never reach this public repo.** Test locally only — copy the file to a scratchpad/git-ignored location (never into this tracked directory), delete it once done, and describe it generically everywhere the description ends up committed (code comments, commit messages, this file, the README): "a real multi-sheet lab workbook," not the company name, study name, or any other identifying specifics. This is a hard-won rule — a company name once leaked into two code comments and had to be scrubbed from GitHub's history after the fact (`git commit --amend` + `git push --force-with-lease`, since a follow-up commit alone leaves the old one visible in history). Grep the diff for anything identifying before every push, not just eyeball it.

**Regression-check worked examples** after touching `shared.js` (all previously hand-verified against real math):
- Simple: C1=10mM, C2=1mM, V2=5mL → V1=500µL, diluent=4.5mL
- Serial (constant): stock=1mM, DF=10, 5 steps, 1mL/step → 100µM/10µM/1µM/100nM/10nM
- Secondary stock (direct case): C1=10mM, C2=1mM, 5mL final, 2µL min → mode `direct`, matches the Simple example exactly
- MSD default: 7pt, 4-fold, top=10000 pg/mL → S1=10000, S2=2500, S3=625, S4=156.25, S5=39.0625, S6=9.765625, S7=2.44140625, Blank=0

**MSD real-kit validation** (checked against actual published product-insert calibrator tables, not just our own default — see sources below): `generateMsdPlate`'s raw output matches every published value exactly once rounded to the kit's own printed precision, for all three kits tested, including a non-4-fold dilution factor:
- MSD Human Angiopoietin-2 Kit (insert 17929-v2-2012Apr): 7pt, 4-fold, top=10000 pg/mL → 10000/2500/625/156/39/9.8/2.4/0 pg/mL (kit's STD-01–08). Matches exactly.
- MSD Human Myeloperoxidase (MPO) Kit (insert 17036-v3-2013Jan): 7pt, **3-fold** (not 4-fold), top=50000 pg/mL → 50000/16667/5556/1852/617/206/69/0 pg/mL. Matches exactly — confirms the dilution factor field isn't hardcoded to 4-fold assumptions anywhere in the math.
- MSD Human Cytokine Ultra-Sensitive Kit insert (17061-v6-2010Mar, generic single-analyte format e.g. TNF-α): 7pt, 4-fold, top=2500 pg/mL → 2500/625/156/39/9.8/2.4/0.61/0 pg/mL. Matches exactly.
- Only observed divergence is cosmetic: `formatNumber()` always shows 4 significant figures (e.g. "205.8"), while MSD's own printed tables inconsistently round to 2–3 sig figs per value (e.g. "206") for pipetting-instruction readability. The underlying raw values are exact in both cases — this is not a bug, just a display-precision choice, and 4 sig figs is arguably more useful for a calculator than a print table's simplification.
- Also confirmed against the MSD V-PLEX Proinflammatory Panel 1 (human) insert (18094-v6-2025Mar, a 10-plex kit): protocol text explicitly describes "7 calibrators" via 4-fold serial dilution plus a zero calibrator — matches the tool's default shape, though multiplex panels don't publish one fixed top-calibrator number in the insert itself (it's lot-specific, per the kit's Certificate of Analysis, and differs per analyte within the same physical dilution series).
